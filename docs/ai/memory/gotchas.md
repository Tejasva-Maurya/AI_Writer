# Gotchas (verified traps)

> Auto-loaded into every Claude session. Only verified, still-true traps. Delete an entry once the code no longer has the trap (and note that in `docs/CHANGELOG.md` and `docs/technical/09`).

- **Run uvicorn from `app/backend/`** (or pass `--app-dir app/backend`). `uvicorn main:app` resolves `main` from the CWD. The flat imports work anyway because `main.py:19` patches `sys.path`, and data paths come from `__file__`. (2026-11-22)
- **The specialist is async.** Every `specialist.*` function is `async def`; call it with `await` (a missing `await` returns a coroutine, not a dict, and `.get()` then fails). Never use the sync `ollama.chat` in async code (KI-005, plan 005). (2026-11-22)
- **Slugs are server-derived and validated.** `slug` is still a required body field (send `""`), but POST stores `make_slug(slug or name)`; an empty result is 422. Managers accept only `[\w-]+` via `_path()`; never build `data/` paths from request or LLM strings (KI-009/KI-010, plan 007). (2026-11-23)
- **Create returns 409 for a taken or equivalent slug** (same `_slugify`: case, `-` vs `_`; e.g. `xiao-fan-scientist-inventor` blocks `Xiao Fan Scientist Inventor`). POST, refine create; step 3 emits a `warning`. Delete `zz_test_` entities before re-running tests (KI-036/KI-009). (2026-11-23)
- **`save()` is an upsert, `create()` is exclusive** (managers). Use `create()` for any new create path, or you reintroduce KI-036. (2026-11-22)
- **Models coerce, and Character/Scene validate on assignment.** Build entities from LLM data through the models (`Character(**d)`), never by `setattr` of raw values; in-place mutation (`c.relationships.update()`, `c.abilities.append()`) bypasses validation, so assign a new value instead. Only a missing `name`/`slug` still fails (plan 009). (2026-11-23)
- **One generation at a time per server process.** A second `POST /api/generate-chapter` gets 409 while one runs (`main.py:180-217`). Tests that generate back to back must wait for `complete`/`error` or call `POST /api/generate-chapter/cancel` first. A test client that drops the stream cancels the generation (plan 010). (2026-11-23)
- **Git Bash `sed -i` turns CRLF files into LF.** Most repo files are CRLF in the working tree (`core.autocrlf=true`). Git normalises on commit, but use the Edit tool or a Python script (bytes in, bytes out) for doc edits to keep endings stable. (2026-11-23)
- **A CSS `display` rule beats the `hidden` attribute.** `.x { display: flex }` overrides the browser's `[hidden] { display: none }`, so `el.hidden = true` does nothing. When you give a toggled element a `display`, add `.x[hidden] { display: none; }` (see `.text-cursor`, `.multi-chapter-notice`, `.mode-panel`). Audit in the browser: `[...document.querySelectorAll('[hidden]')].filter(e => getComputedStyle(e).display !== 'none')` (KI-037/KI-039, plan 011). (2026-11-23)
- **Python 3.11 is the floor; this machine runs 3.14.** Syntax that only 3.12+ accepts (e.g. a backslash inside an f-string expression) passes locally but breaks the app on 3.11 (KI-040). `py -m ruff check app` (target `py311`) and CI catch it. (2026-11-24)
- **`TestClient` needs `base_url="http://127.0.0.1"`.** Its default host `testserver` is rejected by `TrustedHostMiddleware` with 400. The `client` fixture in `app/tests/conftest.py` already does this. (2026-11-24)
- **Two Pythons on the dev machine.** `py` (3.14.5) has the web deps; `python` (3.14.0) is a different install. Use `py` for backend checks. Running `py -I` hides user-site packages. (2026-11-22)
- **Inline scripts with apostrophes break the Bash tool.** A heredoc Python script containing `'` inside strings (e.g. "doesn't") fails with "unexpected EOF while looking for matching `''", and nothing runs. Write the script to a temp file and run that instead. (2026-11-22)
- **Git identity is per clone.** The machine-wide git identity is the work account; this repo overrides it in `.git/config` (D-010). Check `git config user.email` = `mauryatejasva512004@gmail.com` before committing, and set it again after a fresh clone, or GitHub credits the work account. (2026-11-23)
- **The API is same-origin only.** No CORS; `TrustedHostMiddleware` allows `Host` 127.0.0.1/localhost only (other hosts → 400). Test with `http://127.0.0.1:<port>`; a page on another origin can't call the API (plan 007). (2026-11-23)
- **Git Bash curl mangles non-ASCII arguments.** `curl -d '{"name":"林凡"}'` arrives as `??` (looked like a 422 bug). Send UTF-8 bodies from a Python script (`urllib`), and run it without `-I` with `PYTHONIOENCODING=utf-8` to print them. (2026-11-23)
- **`\\$` in Git Bash double quotes swallows the variable.** `PYTHONPATH="$DIR\\$s"` expands to a literal `$s` (the import then fails as if the package were missing). Use a forward slash: `"$DIR/$s"`. (2026-11-23)
- **The API push can fail intermittently.** The `github-push` script broke three times on 2026-11-23 while uploading blobs (a connection reset, then GitHub 400 "malformed request" twice). `main` on GitHub never moved: the ref is updated only after every blob, tree and commit exist. The unchanged retry succeeded on 2026-11-24. Stop after ~3 tries, confirm the remote head with `--preflight`, and retry later. (2026-11-24)
- **Tag the pushed commit, through the API.** The github-push script gives every commit a new SHA, so tag GitHub's copy (`origin/main` after a fetch), never the local SHA. Tags: `POST /git/tags` (annotated) then `POST /git/refs`; Release: `POST /releases`; then `git fetch --tags`. CI (`on: push`, unfiltered) also runs for a pushed tag (plan 018). (2026-11-24)
- **Git Bash noise.** Every Bash call on this machine prints `/etc/mtab`, `/etc/hosts` … "Permission denied" lines from the shell profile. They are harmless; ignore them. (2026-11-22)
- **`data/` is the user's novel.** Never use it as a scratch area. Test with `zz_test_` entities and delete them afterwards. (2026-11-22)
- **`git status` can't see `data/`.** It is git-ignored since plan 017 (D-014), so a changed or deleted novel file shows nothing in git. Check "untouched" with a before/after listing (paths, sizes, mtimes or SHA-256); pytest's `real_data_untouched` guard does this for test runs. (2026-11-24)
